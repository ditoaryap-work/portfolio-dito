## Context and goal

This project focused on staff leave requests and approvals. The goal was to put the request and decision stages into one web system.

The project notes do not describe the previous workflow or the challenges each role faced. This story focuses on the system features that are documented.

## What we built

The application provides a leave request and approval workflow. It was developed with Next.js, Prisma, PostgreSQL, and Tailwind CSS.

## My role and decisions

I developed the application across its interface and database integration. The request form and review screen follow the two main stages: submitting a request and reviewing its outcome.

## Results and impact

The documented outcome is a web system for managing leave requests and approvals. The notes do not report staff adoption, approval time, or changes in administrative workload.

## Trade-offs and questions to measure

A short workflow can make requests easier, but an HR application needs to make the current status clear to both staff and reviewers. Useful next measures would include time to decision, requests that need correction, and whether decisions can be traced later.

## What I learned

An internal system should make the next action visible to each role. In another iteration, I would review the staff and reviewer paths separately so the same status is not interpreted in different ways.
